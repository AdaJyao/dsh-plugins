# dsh-supervisor-tick

DSH **进程内**定时器插件：每 **120 秒**跑一次外部脚本，用来驱动"监督者 / 执行者"工作流里的看门狗。

- **Host-only**：没有界面、没有客户端半边，装了就在后台按点跑。
- **为什么是插件而不是 cron**：DSH 的定时器跑在 DSH 自己的进程里，**不碰系统 crontab、不碰 fnOS 计划任务**，
  升级/迁移时只跟着 DSH 走；也避免"路径含空格被 sh 拆词"这类 cron 坑。
- **为什么不用 DSH 自带的会话级提醒**：那种是投递 prompt 的（不是跑命令），而且最短间隔 300 秒。

## 行为

| 项 | 值 |
|---|---|
| 首跑延迟 | 20 秒（必须 > 0：插件 apply 时 webServer 还没开始监听） |
| 周期 | 120 秒 |
| 动作 | 调一次配置里的命令（默认是本机监督者工作流里的 `watchdog.sh --once`） |
| 日志 | 每行一条 JSON（`seq` / `trigger` / `at` / `durationMs` / `exit` / `stdoutTail`），另有最近一次快照 |
| 失败处理 | 只记录、不重试风暴；命令超时会被杀掉并记为失败 |

`trigger` 有三种：`boot`（插件加载后的第一跑）、`interval`（周期）、`manual`（人工触发一次）。

## 配置

命令与日志路径由插件读取的配置决定（默认值见 `lib/index.js` 顶部常量）。改完需要重启 DSH web。

## 与这个仓库里其它插件的关系

`dsh-model-live`、`dsh-api-balance` 是"给人看"的挂件，本插件是"给流程跑"的定时器 ——
三者都遵守同一条铁律：**只读、不改会话、不注入请求**；本插件唯一的副作用是执行你配置的那条命令。
